# ColdPilot 前端关键决策记录（DECISIONS）

> 记录本阶段影响结构 / 契约的关键取舍，便于后端与后续维护者理解「为什么这么做」。

## D1. 单一数据边界 `ColdPilotClient`
**决策**：所有组件与状态机只依赖接口 `ColdPilotClient`，禁止直接 import mock。
**理由**：mock/http 切换零改动；后端只面向接口编程。这是三道隔离边界的核心。
**代价**：多一层抽象；通过工厂 `api/index.ts` 集中管理实现。

## D2. 只实现 mock，不建 http 空壳
**决策**：本阶段不提供 `HttpColdPilotClient` 空实现，工厂在 http 模式直接抛错「尚未实现」。
**理由**：避免维护一个未被验证的假实现；接口 + OpenAPI + 行为文档已足够后端对齐。
**切换路径**：见 FRONTEND_HANDOFF §9。

## D3. 异步收敛在 Client，UI 不用 setTimeout 模拟后端
**决策**：诊断/执行的异步与渐进揭示全部在 `MockColdPilotClient` 内时间驱动；UI 仅轮询。
**理由**：保证切换真实后端后时序语义一致；防止演示逻辑泄漏进组件。

## D4. 异步任务用「轮询」而非 WebSocket
**决策**：诊断/执行采用「POST 创建 + GET 轮询」两段式。
**理由**：MVP 简单可靠、可幂等重试；与后端无状态实现兼容。生产可加 WS，但契约不变。

## D5. 状态机集中守卫，非法转换返回 null
**决策**：`transition()` 对非法转换返回 `null`，reducer 拒绝；`canTransition` 供 UI 禁用。
**理由**：把「不可能状态组合」挡在源头；守卫单一出处，便于测试（12 个状态机用例）。
**对后端要求**：仍需独立校验（前端守卫不替代后端）。

## D6. 选择方案即仿真
**决策**：`simulatePlan(planId)` 同时把 `activePlanId` 设为该方案；`simulations` 以 `planId` 为键缓存，
支持 A/B 对比。
**理由**：评委动线「选方案→看仿真」一步到位；对比视图直接读取两套缓存结果。

## D7. L2 审批需先仿真 + 二次确认；L3 仅审计不可执行
**决策**：`REQUEST_APPROVAL` 要求方案已仿真且为 L2；UI 批准后弹二次确认；L3 无执行入口，
只产 `SecurityAuditEntry(blocked)`。
**理由**：贴合「AI 分级 + 安全兜底」的产品主张；演示可清晰展示 L2 人工把关与 L3 系统拦截。

## D8. 安全回退是一等状态而非错误页
**决策**：`safeFallback` 作为独立状态，执行/验证失败可进入，随时可人工接管/重置。
**理由**：工业安全语义——失败不应是死路，而是「回退传统规则/PID」。

## D9. provenance 标注贯穿全链路
**决策**：所有数据带 `demo`/`simulated`/`real`，UI 用 `DemoDataBadge` 标注。
**理由**：参赛演示必须诚实——仿真结果绝不表达为真实运行成果。后端须透传。

## D10. 时间统一按 UTC 渲染
**决策**：演示时序基于固定 UTC 参考时间，`formatTime` 用 UTC 取值渲染。
**理由**：保证任意时区下显示与演示叙事一致（如「09:15 起」），避免本地时区偏移。

## D11. 无 UI 框架 / 无全局状态库
**决策**：CSS Variables + CSS Modules；状态用 useReducer + useState。
**理由**：可控、无魔法、便于评审阅读；避免引入冗余依赖。

## D12. 窄屏检查器折叠为把手（而非隐藏）
**决策**：1024–1439px 检查器折叠为可展开的竖条把手；≤1100px 事件列表收窄。
**理由**：保留「检查器是核心」的可发现性，同时给诊断主体让出空间。
