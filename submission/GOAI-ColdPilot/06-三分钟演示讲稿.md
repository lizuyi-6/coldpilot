# 鲜知 ColdPilot 三分钟演示讲稿

## 0:00–0:25｜场景与一句话价值

大家好，我们的项目是鲜知 ColdPilot，一款面向果蔬冷库的安全可控工业 Agent。

冷库发生持续高温时，值班员需要跨传感器、库门、设备、库存和 SOP 查找原因，还要在恢复速度、能耗、货品风险和设备安全之间做决定。ColdPilot 的目标不是替人拍板，而是把诊断做深、把边界做硬、把结果做实。

## 0:25–1:05｜Agent 自主诊断

现在首页已经检测到 1 号辣椒库持续高温。无需聊天输入，Agent 会自动调用五类工具：遥测、库门记录、设备日志、冷库知识和历史案例。

每次调用的输入、输出、摘要、耗时和状态都会留痕。系统随后给出原因排序、置信度、支持证据、反向证据和需要现场核查的不确定项，因此结论不是一个无法追溯的黑盒答案。

## 1:05–1:40｜方案与仿真

诊断完成后，系统衔接两套候选控制方案，并在控制前运行热力学仿真。这里可以同时比较恢复时间、预计能耗、过冲风险、冻害风险和压缩机启停次数。

请注意，当前页面中的业务数据来自演示种子，效果数值来自仿真模型，我们不会把它们表述成真实客户成效。真实落地前需要用冷库历史数据完成模型校准。

## 1:40–2:20｜安全与人工审批

ColdPilot 最大的差异化是：安全不写在 Prompt 里，而是由确定性规则和人类授权共同保证。

L2 控制方案必须展示参数、当前值、目标值和允许范围，并绑定方案版本，等待冷库管理员审批；版本变化后旧审批失效。执行前系统还会再次检查参数白名单、上下限、变化速率、冲突和权限。

如果 Agent 提议关闭压缩机联锁并强制满负荷降温，系统会将其识别为 L3 永久禁止动作。它只写入安全审计，不会创建方案、审批、命令或执行任务。

## 2:20–2:45｜执行与验证闭环

人工批准后，系统生成结构化控制命令并进入仿真执行。执行完成并不等于事件恢复，任务还必须进入效果验证；只有最终温度回到安全区间且验证成功，事件才会被标记为恢复并生成报告。

## 2:45–3:00｜现状与落地计划

当前项目已经完成 React + FastAPI 全栈 MVP，具备 10 个业务模块、13 个业务 API、5 类 Agent 工具和 15 阶段工作流，并有 109 项自动化测试通过。

下一步我们将按照只读试点、影子仿真、L1 建议运行和受控 L2 接入四个阶段进入真实冷库，同时永久保留 L3 禁止边界。谢谢。

## 评委追问时的事实口径

- 默认 Agent 是离线确定性 Agent；OpenAI 兼容 LLM 是可选诊断综合模式。
- 候选控制方案当前为演示种子数据，不宣称由大模型动态生成。
- 当前执行为仿真回放，尚未接入真实 PLC。
- 当前没有真实客户试点、节能率、货损降低率或诊断准确率数据。
- LLM 不参与安全、审批、控制命令或执行。
